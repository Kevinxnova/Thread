# 留绪 · Thread

**留住思路，随时继续。**

*Pick up where you left off.*

[English](README.en.md) · 简体中文

Thread 是一款原生 macOS 工作管理应用，把应用窗口、具体网页、目标和笔记联系起来。给正在做的事情留下一个标签，下次点击它，就能回到对应窗口或页面，继续未完成的思路。

当前版本 **0.8**。本次公开源码基于已在本机验收的 0.7 功能，增加中英文文档与代码发布检查。应用界面目前以中文为主。

## 能做什么

- **留住工作现场**：选择应用窗口或网页，填写目标，生成独立编号和自动保存的 Markdown 笔记。同一来源可以对应多个目标。
- **随时继续**：点击编号标签，唤回对应窗口或网页，打开笔记，并把关联的实时镜像放到其他镜像前面。
- **按需置顶**：在 SIP 保持开启的情况下，以实时镜像浮窗持续展示内容；新置顶的镜像优先。可以随时取消置顶并保留任务。
- **轻量记录**：可拖动、缩放的笔记框；关闭窗口或网页不会自动完成任务。
- **统一管理**：三图标悬浮条提供添加标记、工作条项、完整总览入口。支持搜索、星标、排序、完成和撤回；最近三条完成事项以灰色显示，删除需确认。
- **完整总览**：渲染本地 Markdown 总览，固定展示「编号 · 目标 · 当前打开网页/应用 · 笔记」，配合笔记侧栏；“全部打开”可查看当前可枚举的窗口。
- **原生界面**：使用 AppKit、SwiftUI、系统字体与浅色/深色外观。

> 持续置顶的是 Thread 创建的实时镜像，并非修改其他应用原窗口的层级。原应用继续运行。镜像中的点击与滚动是实验功能；键盘输入及复杂交互请返回原窗口。最多同时镜像 6 个来源窗口。

## 从源码运行

需要 macOS、Swift 5.9 或更新版本，以及可用的 macOS SDK。项目最低部署目标为 macOS 13；本机完整工作流验收环境为 **macOS 15.6 / Apple Silicon**。其他环境的兼容性尚未全面验证。没有第三方包依赖。

```sh
git clone https://github.com/Kevinxnova/Thread.git
cd Thread
python3 scripts/check-repository.py --all-history
swift test
./scripts/build.sh
open dist/Thread.app
```

构建脚本生成本机架构的应用，使用临时签名；不包含 Developer ID 签名或 Apple 公证。仓库提供源码，不包含安装包、构建缓存和个人数据。

首次使用按系统提示授予屏幕录制、辅助功能权限；识别和定位浏览器页面还可能需要自动化权限。无需关闭 SIP。

1. 点击悬浮条的标签图标，选择来源并填写目标。
2. 点击桌面编号标签，继续来源窗口和笔记中的工作。
3. 在工作条项中排序、星标、完成或撤回；使用第三个图标阅读完整总览。

## 数据属于你

默认数据目录为当前用户主目录下的 `~/Thread_kevin/`，独立于代码仓库：

| 文件 | 用途 |
| --- | --- |
| `总览.md` | 可独立阅读的四列 Markdown 总览 |
| `笔记/000001.md` | 按编号保存的元数据与笔记正文 |
| `.thread/store.json` | 已使用编号的高水位，避免重复编号 |
| `.thread/conflicts/` | 外部编辑冲突时保留的副本 |

无需账号或云端服务。镜像画面在内存中处理，不主动保存为录屏文件；应用没有任务或笔记上传功能。网页唤回会交给相应浏览器处理。终端可能输出运行诊断；设置 `THREAD_MIRROR_LOG` 可额外写入本地日志，分享前应审查内容。

外部编辑编号笔记时，建议只修改第二个 `---` 分隔线之后的正文，并保留元数据与编号状态。总览遭外部编辑时，应用暂停自动覆盖，提供备份后重建。

开发时可通过 `THREAD_DATA_DIR` 指定独立测试目录。**不要把个人任务、网页记录、笔记或验收日志提交到此仓库。** 详见[贡献与发布检查](CONTRIBUTING.md)。

## 验证与兼容范围

- 0.7 已在上述本机环境完成 64 项自动测试，以及原生窗口、Chrome 页面、标签恢复、共享镜像、笔记保存和浅深色界面的工作流验收；详细原始日志保持本地，不随源码上传。
- 普通 `swift test` 会跳过真实废纸篓测试。执行 `THREAD_TEST_REAL_TRASH=1 swift test` 可启用它，仅操作测试生成的临时笔记。
- 网页镜像捕获的是浏览器窗口，页面变化时会清空画面并阻止输入，重新匹配后恢复；它不是独立的后台标签页渲染器，检查存在短暂延迟。
- Safari、Edge、Brave 的识别路径已实现，但没有与 Chrome 相同范围的实机验证。其他 macOS 版本、Intel、多物理显示器、全屏/Spaces 组合、受保护内容、长期功耗和完整 VoiceOver 流程仍需验证。
- 镜像输入转发包含未公开的系统接口，系统升级后可能失效；当前版本不声明 App Store 上架兼容性。
